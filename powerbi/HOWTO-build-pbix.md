# Как собран BA_Cases_Dashboard.pbix

Файл уже лежит в этой папке. Ниже — как он собирался, чтобы его можно было воспроизвести или пересобрать после изменения CSV. Нужен Power BI Desktop (бесплатно, Microsoft Store). Время — 30–40 минут.

Два отличия от `measures.dax`, на которые стоит обратить внимание: базовые суммы называются `Numerator Sum` / `Denominator Sum` (Power BI не даёт мере имя, совпадающее со столбцом), а меры «до/после» сами подставляют сегмент «Всего», если сегмент не выбран явно — иначе у AirTrack карточки складывали бы «Всего» с разрезами «Интерфейс» и «Интеграция». Меры добавлялись через представление TMDL одним скриптом, а не по одной.

## 1. Загрузка данных

1. Главная → Получить данные → Текст/CSV. Выбрать `data/dim_case.csv`.
2. В окне предпросмотра: источник файла — «65001: Юникод (UTF-8)», разделитель — «Точка с запятой». Нажать «Преобразовать данные».
3. В Power Query проверить типы: все столбцы `dim_case` — Текст.
4. Повторить для остальных четырёх файлов. Типы: `numerator`, `denominator`, `count`, `active_seconds`, `observation_no`, `n_observations`, `median_seconds` — Целое число; `period`, `case_id`, `metric_id`, `reason`, `segment`, `good_direction` — Текст.
5. Закрыть и применить.

## 2. Модель

1. Вкладка «Модель». Перетащить `dim_case[case_id]` на `case_id` каждой из четырёх фактовых таблиц.
2. Для каждой связи: кратность «Один ко многим (1:*)», направление кросс-фильтрации «Одно», «Сделать связь активной».
3. Проверить, что между фактовыми таблицами связей нет — если Power BI создал автоматически, удалить.
4. Скрыть из отчёта столбцы `case_id` в фактах (правый клик → Скрыть в представлении отчёта), чтобы в визуалах использовался только `dim_case`.

## 3. Меры

1. Выбрать таблицу `fact_metric` → Моделирование → Создать меру.
2. Открыть `measures.dax`. Быстрый путь — представление TMDL (значок слева): `createOrReplace` → `ref table fact_metric` → строки `measure 'Имя' = выражение` с отступом табуляцией, «Применить». Медленный — копировать меры по одной: имя до знака `=`, выражение после. Меры про доли — в `fact_metric`, про причины (`Reason …`) — в `fact_reason`, про время (`Median …`, `Observations …`) — в `fact_timing_rows`, `Cases Count` и `Improved Cases` — в `dim_case`.
3. Формат: `Share`, `Share Before`, `Share After` — десятичное число, 3 знака (не процент — иначе визуалы будут показывать «35 %», а мы договорились показывать дроби); `Delta pp` — десятичное, 1 знак.
4. Контроль: создать временную таблицу-визуал с `case_name`, `Label Before`, `Label After`. Ожидаемые значения: AirTrack «13 из 37» → «6 из 41», HarborWatch «9 из 26» → «3 из 29», KioskCare «31 из 58» → «55 из 67», TransitDesk «49 из 143» → «18 из 157», BeautyCatalog «43 из 61» → «60 из 67», PartnerFlow «34 из 127» → «12 из 139». Если хоть одно не совпало — проблема в типах или разделителе CSV.

## 4. Страницы

Собрать по `dashboard-layout.md`, четыре страницы. Порядок сборки: сначала срез компании на странице «Итоги» и синхронизировать его (Вид → Синхронизация срезов) на все страницы; потом карточки и гистограмма; потом страница «Кейс» с drillthrough по `dim_case[case_name]`.

Для box-and-whisker на странице «Время»: Визуализации → «…» → Получить дополнительные визуальные элементы → «Box and Whisker chart» (MAQ Software или xViz). Если ставить custom visual не хочется — точечная диаграмма: ось X `period`, ось Y `active_seconds`, «Показать все» точки.

## 5. Проверка перед публикацией

В `fact_reason` для TD, BC, PF мера `Reason Check` показывает «ок» в обоих периодах. `Median Seconds Before Rows` = 1044, `Median Seconds After Rows` = 738. На странице «Итоги» шесть карточек, у всех `Improved` = 1 (все шесть метрик двигались в нужную сторону — это реальный результат, но на странице «Методика» обязательно есть оговорка про причинность).

## 6. Скриншоты

Файл → Экспортировать → Экспорт в PDF, затем страницы PDF в PNG (1600 px по ширине) в `powerbi/screenshots/` — они вставлены в README, чтобы дашборд был виден без установки Power BI.
