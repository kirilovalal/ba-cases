# Макет дашборда

Четыре страницы, формат 16:9, единый фильтр «Компания» в шапке каждой страницы. Цвета: «до» — серый `#9AA5B1`, «после» — синий `#1F3A5F`, улучшение — зелёный `#2E7D32`, ухудшение — красный `#C62828`. Никаких процентов в карточках — только «n из N» и п.п.

## Страница 1 — «Итоги»

Назначение: за 10 секунд увидеть шесть результатов и убедиться, что все считались одинаково.

| Зона | Визуал | Поля / меры | Примечание |
|---|---|---|---|
| Шапка | Срез (кнопки) | dim_case[company] | Softintermob / Cetera / оба |
| Ряд KPI, 6 карточек | Карточка с несколькими строками | dim_case[case_name]; [Label Before] → [Label After]; [Delta Label] | Одна карточка на кейс; фильтр `segment = Всего`; цвет [Delta Label] по [Improved] |
| Центр | Кластеризованная гистограмма | Ось: dim_case[case_name]; значения: [Share Before], [Share After] | Ось Y в долях 0–1, подписи данных — [Share Label] через tooltip |
| Низ | Таблица | case_name, metric_name, unit_of_analysis, period_before, [Label Before], [Label After], [Delta pp], [Improved] | Условное форматирование [Improved]: 1 — зелёная точка |
| Подвал | Текстовое поле | — | «Доли — по агрегатам; разница в п.п.; причинность не устанавливалась» |

## Страница 2 — «Кейс»

Назначение: один кейс подробно. Верхний срез по `dim_case[case_name]` (single select).

| Зона | Визуал | Поля / меры |
|---|---|---|
| Слева | Карточки | [Label Before], [Label After], [Delta Label], dim_case[unit_of_analysis], dim_case[observation_window] |
| Центр | Линейчатая с двумя сериями | Ось: fact_reason[reason]; значения: [Reason Count Before], [Reason Count After] |
| Справа | Карточка | [Reason Check] — должно быть «ок» |
| Низ (только AirTrack) | Кластеризованная гистограмма | Ось: fact_metric[segment]; значения: [Share Before], [Share After] — разрез интерфейс / интеграция |

Для HarborWatch и KioskCare `fact_reason` пуст — визуал причин скрыть условным отображением или оставить с подписью «распределение причин не фиксировалось».

## Страница 3 — «Время»

Назначение: активное время обработки — единственные построчные данные.

| Зона | Визуал | Поля / меры |
|---|---|---|
| Верх | Карточки | [Median mm:ss] по периодам, [Observations], [Median Delta Seconds Rows] |
| Центр | Box-and-whisker (custom visual из AppSource) или точечная диаграмма | fact_timing_rows[active_seconds] по fact_timing_rows[period] |
| Справа | Таблица | fact_timing_agg: case_name, period, n_observations, median_seconds, note |
| Подвал | Текст | «TransitDesk — 17 и 19 наблюдений у тех же трёх менеджеров; KioskCare — медианы внесены агрегатами, исходные длительности не приложены; ожидание клиента исключено» |

## Страница 4 — «Методика»

Без визуалов данных: таблица `dim_case` целиком плюс текстовые блоки с ограничениями вывода. Эта страница — то, что показывают нанимающему, когда он спрашивает «а как вы это считали».

## Взаимодействия

Срез компании фильтрует все страницы (синхронизация срезов). На странице «Итоги» клик по столбцу кейса ведёт на страницу «Кейс» с этим кейсом (drillthrough по dim_case[case_name]). Кросс-выделение между визуалами разных фактов отключить в «Формат → Взаимодействия».
